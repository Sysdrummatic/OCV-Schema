# Git workflow

Canonical source for branches, commits and issue/PR naming. Referenced from `CLAUDE.md` (via `@import`), `AGENTS.md` and `.codex/instructions.md`; do not copy it elsewhere.

## Project element naming

Every project element (issue, PR, branch, task) is identified as `ocvs-<xyzt>-<rest-of-text>`:

- `ocvs` — OCV Schema (distinguishes it from `ocv-` used in OpenCiVera).
- `<xyzt>` — number of the GitHub issue/PR, zero-padded to 4 digits (`0001`). Open the issue (or a draft PR) first and use its number.
- `<rest-of-text>` — short description in kebab-case, without a change-type prefix.

## Branches

- Start every task on a fresh branch when on `master`; keep branches short-lived and scoped to one goal.
- Format: `ocvs-<xyzt>-<rest-of-text>`, e.g. `ocvs-0001-add-migration-registry`.
- Branches created before this convention (`feat/ocv-schema-foundation`) stay as they are.

## Commits and PR titles

Each commit and each PR title uses Conventional Commits with the number from the branch name as scope — no exceptions, no scope-less form:

`<type>(ocvs-<xyzt>): <Text of the commit>`

Types: `feat`, `fix`, `refactor`, `docs`, `test`, `chore`. The text starts with a capital letter, is imperative and has no trailing period.

Examples:

- `feat(ocvs-0001): Add migration registry`
- `fix(ocvs-0002): Reject unknown locale codes`

Keep commits atomic; do not mix refactors with behavior changes.

## No AI attribution

Do not add footers or notes saying a commit, PR or comment was generated by an AI agent (no `Generated with Claude Code`, no `Co-Authored-By: Claude ...`, no Codex equivalent). This overrides tool defaults.
